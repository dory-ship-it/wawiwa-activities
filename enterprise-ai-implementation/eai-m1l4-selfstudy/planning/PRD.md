## 1. Purpose and pilot framing

EAI Module 1, Lesson 4 "Process Modeling and Workflow Mapping" is the first lesson of the new self-study format: a Storyline-style module built in code, uploaded to Blossom as SCORM 1.2. Everything here is a pilot: the screens, the five templates, the video player, the tracking and the planning process are evaluated before the format is applied to other lessons and programs.

The slice proves the whole chain end to end on a small set of screens: templates, menu, feedback row, a real narrated video with in-video questions, a handoff to an existing Practice Studio workbook and back, SCORM reporting, and a local preview mode.

## 3. Decision: fork or reuse the GFM S1 engine

Inspected `genai-for-marketing/s1-ai-awareness/`. **Decision: new engine, lifting proven parts from GFM S1 by copy (not import).**

Why not reuse the engine as is:
- GFM S1 is a Storyline replica. `engine.js` + `screen.js` render geometry from `src/screens/layout.json` (extracted from Storyline slide data) and vector art from Storyline's `paths.js`. L4 is template-driven from a content JSON; none of that geometry applies.
- Its frame is the Storyline player (960x540, PREV/NEXT bar, slide menu, swipe). L4 needs 1280x720, three fixed zones, Continue only after correct, a chapter menu, SCORM.
- `svg.js`, `text.js`, `anim.js`, `slider.js`, `dragdrop.js`, `components/`, `sync/`, `tools/extract-*` are Storyline-specific.

What is lifted (copied into `eai-m1l4-selfstudy/`, each file headed "adapted from genai-for-marketing/s1-ai-awareness/<file>"):
- Stage scaling math (`engine.js` fit-to-container, about lines 190 to 220): fixed stage, `transform: scale()`, letterbox.
- `captions.js`: `parseVTT` and the caption strip placed under the media, never over it.
- `store.js` pattern: every storage access in try/catch.
- `index.html`: strict CSP, `src/main.js` module entry, `#boot-error` with the file:// message.
- `tools/test-fit.mjs` harness: tiny static server + puppeteer-core + the machine's Chrome (`CHROME_PATH`), clipped-text checks, `--shots`. Rewritten for L4 screens and states.
- `tools/check.mjs` idea: a build check on the content JSON (schema, files exist, word limits, no em dash).
- `package.json` scripts shape and the `.github/workflows/s1-check.yml` pattern (optional, P5).

From Practice Studio: the SCORM API discovery walk and the identity-field guard from `engine/passback.js` (copied into `src/tracking/scorm12.js`, 1.2 only); the colour values in `engine/skins/selfstudy.css`; the Wawiwa logo base64 from `enterprise-ai-implementation/_wawiwa-logo.b64`.

## 5. Content JSON schema (`content/l4-slice.json`)

Top level: `schemaVersion`, `lesson`, `ui`, `links`, `tooltips`, `characters`, `chapters`, `screens`.

- `lesson`: id, code, program, title, `lang`, `dir`, contentVersion, `slice` (screen order), `completion` (`rule`, `statusWhenNoScoredItems`, `passMark`, `scoredScreens`).
- `ui`: every chrome string (buttons, menu, help, resume, start over, counters with `{n}/{max}`, feedback prefixes, screen-reader-only strings). Placeholders in braces. Marked `pilotCopy` (new copy, Noy reviews).
- `links`: named URLs; screens refer to them as `"@links.workbook"`.
- `tooltips`: term to definition. A screen lists `terms`; the engine underlines the first occurrence of each on that screen.
- `characters.<id>`: name, role, `fictional`, label, `avatar` {`src` (null = placeholder), `alt`, `placeholder`, `source`, `credit`}.
- `chapters[]`: id, n, title, minutes, screens, `inSlice`, `fastTrack` {card, landing}, `pauseMarker` (shown in the feedback row after the chapter's last screen).
- `screens[]` common fields: `id`, `chapter`, `template` (decision | input | handoff | video; later sort | explorer), `variant`, `minutes`, `instruction`, `hint` (feedback row before action), `terms`, `stage` {`top`, `middle`, `bottom`} each with a `kind` (character, line, question, title, options, fields, steps, privacy, action) and its role content, `advance` (after-correct | after-save | after-all-answered | after-any | after-video-end), `endOfChapter`, `endOfSlice`, `tracking[]`, `suspend[]`, `sources`.
- Decision: `options[]` {id, label, icon, correct, feedback, term}; `select` (multi); `feedbackPaging`; `attempts`; `routing` (challenge); `steps[]` (selfcheck: `rows` with `choices` and per-choice feedback, `chips` with feedback and `strip`).
- Input: `fields[]` {id, label, placeholder, maxLength (250), multiline, store, trackingId}; `feedback` {saved, empty}; `saveAlwaysEnabled`.
- Handoff: `states.brief` and `states.return` (each its own `stage` and feedback lines), `handoff` {activity, href, newTab, rel}.
- Video: `title`, `guidingQuestion`, `media` {src, poster, captions[], cues, transcript}, `stopLayout`, `stops[]` {id, cueId, question, options[], tracking}, `production` (segments with narration, onScreen keywords, build notes, `stopAfter`; read by P2 only).
- Tracking object (on every interaction): `id` (L4_S01_1 style), `type` (choice | matching | fill-in), `multiple`, `correctResponse` (null when none), `scored` (false = practice), `bloom`, `result` (`graded` = correct/wrong on first attempt, `neutral` = always neutral).

**Response encoding (SCORM 1.2 safe):** choice responses are sent as option letters in on-screen order (`a`, `b`, `c`; multi = `b,d`; Yes/Not yet = `a`/`b`); fill-in sends the text, trimmed, max 250 chars. The long ids stay inside the lesson.

**Video cue file** (`assets/video/v1.cues.json`, written by P2, never by hand): `{ "id": "v1", "duration": <s>, "fps": 25, "stops": [ {"id": "stop1", "t": <s>}, {"id": "stop2", "t": <s>} ], "segments": [ {"n": 1, "t": <s>}, ... ] }`. Content JSON holds what a stop asks; the cue file holds when.

## 7. Tracking

Adapter is chosen at boot: SCORM 1.2 API found (parent chain, then opener chain) = `scorm12`; otherwise `none` (local). `?tracking=` overrides.

**SCORM 1.2 (`scorm12`).**
- `LMSInitialize`; read `cmi.core.entry` and `cmi.suspend_data`; resume if `resume`.
- `cmi.core.lesson_location` = current screen id. `cmi.core.exit` = `suspend` until the slice ends, then `""`.
- Status: `incomplete` on first launch; at slice end `completed` (no scored items in the slice). With scored items (later S21): `cmi.core.score.raw` 0 to 100, min 0, max 100, status `passed` or `failed` against `passMark`.
- `cmi.core.session_time` (HHHH:MM:SS.SS) on every commit of a session end, and `LMSCommit` after each interaction and each screen change.
- Interactions: on the FIRST attempt only, write `cmi.interactions.n.id`, `.type` (choice | matching | fill-in), `.student_response`, `.result` (correct | wrong | neutral), `.latency` (HHHH:MM:SS.SS, screen shown to first answer), `.time` (HH:MM:SS), `.correct_responses.0.pattern` when known, `.weighting` 1 for scored, 0 for practice. Read `cmi.interactions._count` for n. Retries, routes (FT1 skip/full), handoff open/return and clicks go to suspend_data only.
- Never read or write any identity field (`student_id`, `student_name`). The guard throws if any code tries.
- `LMSFinish` on `pagehide` / `beforeunload`.

**suspend_data (< 4096 chars, target < 1500).** Compact JSON with short keys, for example `{"v":1,"s":"S03","d":["S01","S02"],"a":{"S01":"b1","FT1":"b1"},"r":"f","f":{"t":"...","p":"...","m":"..."},"h":{"o":1,"b":0},"x":{"S03":2}}` (d = done, a = first answer + attempt flag, r = fast-track route, f = stored free text, h = handoff flags, x = retry counts). Free text is the bulk: 3 fields x 250 = 750 chars max. The codec asserts length and drops `x` first if over 3800.

**Local mode (`none`).** Same state object in `localStorage` key `wawiwa.eai.l4.slice` (try/catch). `?debug=1` shows a side panel listing the SCORM calls that would have been made, so the GitHub Pages preview doubles as a tracking review.

## 8. Accessibility (WCAG 2.1 AA, hard requirement)

- `lang="en"` from content; all text real text (no text in images; video keywords are in the captions/transcript).
- Keyboard: every action reachable with Tab, activated with Enter or Space; option grids also arrow-key navigable; no drag-only; visible focus (3 px navy outline, 2 px offset, on white and grey).
- Focus moves to the instruction line (tabindex -1, an h1 per screen) on every screen change; after a correct answer focus goes to Continue.
- Feedback row is `aria-live="polite"`, with state words in text ("Correct.", "Not this one."), not colour alone.
- Inputs have labels and `aria-describedby` to counter and privacy line; 250 max enforced with `maxlength`.
- Meaningful SVGs have `role="img"` and a name; decorative ones are `aria-hidden`.
- Contrast: body and emphasis at least 4.5:1, UI borders 3:1 (token table above); turquoise never as text.
- Video: captions (VTT) on by default in the player strip, transcript button, stops announced, keyboard-operable controls, no autoplay with sound before the learner presses Play.
- Motion: `prefers-reduced-motion` disables transitions and the avatar/option entrance motion.
- Menu and dialogs: `role="dialog"`, `aria-modal`, focus trap, Escape closes, focus returns to the opener.
- New-tab links say so ("Opens in a new tab").
- Release gate: axe (0 serious/critical), keyboard walk-through, screen reader pass (NVDA), recorded honestly in the VPAT (CLAUDE.md of Practice Studio).

## 10. Risks

| Risk | Mitigation |
|---|---|
| Video toolchain on Windows (ffmpeg, Python, kokoro-onnx, Chrome) missing or slow | P2 starts with a preflight that stops with exact install commands; render at 1280x720 25 fps |
| Cue times drift from the storyboard (title card, real speech length) | Cue file is generated from the actual audio placement, never typed; storyboard times are labels only |
| White on red CTA fails contrast at small sizes (4.12:1) | Buttons are 20 px bold minimum (large text); `check.mjs` asserts the token |
| SCORM 1.2 strictness in Blossom (response formats, 4096 suspend limit) | Letter-coded responses, compact codec with length assert, SCORM Cloud test, then a Blossom test course |
| Avatar asset late or looks like a real person | Placeholder ships; asset rules in section 6; Noy approves the still |
| Video size in the SCORM zip | crf 23 at 1280x720, target under 15 MB |
| Workbook opened in a new tab is blocked by the LMS sandbox | `window.open` from a click only; fallback visible link; test in SCORM Cloud and Blossom |
| `interactions` are write-only in 1.2: start over cannot erase them | Start over clears suspend_data only; the dialog says sent answers stay (ui.startOverLmsNote) |
| New UI copy not in the storyboard (`pilotCopy`) | Listed in the P5 report for Noy to approve |
| Planning time estimate (FL15) unvalidated | Pilot with two learners; record timings |
